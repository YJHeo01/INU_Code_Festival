문제 링크 : https://www.acmicpc.net/problem/32378

<ul> 
  <li>이 문제는 처음 볼 때, N*(k+1) 사이즈 dp 테이블을 선언하고, 점화식을 세워 dp를 이용해서 풀면 되지 않을까?라는 생각을 유도한 문제입니다.</li>
  <li>그러나, 시간복잡도 및 공간복잡도 개념을 아시는 분은 입력 조건을 보고, 처음 생각한 발상이 틀렸다고 생각했을 겁니다..</li>
  <li>시간복잡도 측면에서 접근하면, 위 풀이의 시간복잡도는 O(N*k)이고, 200,000 * 100,000 = 200억이므로, 시간제한 1초를 초과할 수 밖에 없습니다. </li>
  <li>공간복잡도 측면에서 접근하면, k = 100000일 경우, n * (k+1) 사이즈의 dp 테이블을 선언하면 메모리 제한을 초과할 수 밖에 없습니다. </li>
  <li>그러나, 사실 처음에 생각나는 발상이 문제를 푸는 방법이 맞습니다. 그러나, 수학적인 관찰이 추가적으로 필요합니다.</li>
  <li>2의 37제곱은 137,438,953,472입니다.</li>
  <li>k = 37일 때, 최선을 다해 횃불이를 키우는 경우 중 크기가 가장 작을 때를 나타내는 데이터는, N = 200,000, k = 37, s = 1, Ai = –500 (1<=i<=N)입니다.</li>
  <li>위 테스트 데이터에서 최선을 다해서 횃불이를 키울 경우, 횃불이를 처음부터 37번 강화를 해주고, 이후 먹이를 계속 섭취하면 됩니다. 이 때, 횃불이의 크기는 137,438,953,472 - (200,000 – 37) * 500 = 137,438,953,472라는 값이 나오고, 1000억을 넘습니다. 따라서, k가 36을 넘을 경우, 무조건 Mega를 출력하면 됩니다.</li>
  <li>이제 k <= 36인 경우를 생각해봅시다.</li>
  <li>N * (k+1) 사이즈의 dp 테이블을 생성하고, i일차에 j번 강화를 했을 때 횃불이의 크기를 dp[i][j]라고 생각하고, 점화식을 실행하는 프로그램을 작성하면 문제를 해결할 수 있습니다.</li>
  <li>Python에서는 자리수가 3000을 넘지 않는 경우 오버플로우를 신경쓸 필요가 없지만, C++ 등 언어에서 오버플로우는 상당히 중요한 이슈입니다. 64비트 정수 자료형의 표현 범위를 넘는 경우 __int128을 사용하거나 구조체나 클래스를 새로 정의해야 하기 때문입니다. 그렇기에 이 문제를 64비트 정수 자료형만으로 해결할 수 있는지 알아보겠습니다.</li>
    <li>사실, 이 문제에서는 최대값이 64비트 정수 자료형에서 오버플로우가 발생할 경우, 다른 값이 1000억 이하가 되거나 강화 횟수별 n일차 횃불이 크기 모두 오버플로우가 발생하는 테스트 케이스를 만들지 못해서, 오버플로우를 엄밀하게 신경쓰지 않아도, AC 판정을 받을 수 있습니다. 그래도.... 한번 오퍼플로우에 대해 생각해봅시다. </li>
  <li>우선 k > 37이상인 경우는 위에서 언급한 수학적인 관찰을 토대로 바로 Mega를 출력하면 되니 생략하고, k가 36보다 작거나 같을 때 가장 큰 횃불이의 크기를 나타내는 데이터는 N = 200000, k = 36, s = 100, Ai = 500 (1<=i<=N)입니다. </li>
  <li>이 데이터의 경우 (200,000–36)일까지 먹이를 섭취하고, (200,000-36)일부터 200,000일까지 강화를 할 때 횃불이의 값이 가장 커집니다. 이 때 횃불이의 크기를 계산하면 (200000 * (500-36)+100)*(2**36) = 6,377,174,313,048,473,600으로 C++은 범위가 –9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807인 64비트 정수 자료형 long long int를 사용하면 오버플로우가 발생하지 않습니다. </li>

</ul>
